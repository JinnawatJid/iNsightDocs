# มาตรฐานการตั้งชื่อไฟล์เอกสาร (File Naming Standard)

เอกสารฉบับนี้อธิบายถึงมาตรฐานการตั้งชื่อไฟล์สำหรับผู้ใช้งานระบบ (Users) ก่อนทำการอัปโหลด และอธิบายกลไกการจัดเก็บไฟล์ของระบบ (Backend Storage Mechanism) สำหรับผู้ดูแลระบบ (Administrators/Auditors) เพื่อให้การจัดการเอกสารมีความปลอดภัย ค้นหาง่าย และป้องกันปัญหาไฟล์ทับซ้อน (Overwrite)

---

## 1. สำหรับผู้ใช้งาน (User Guidelines)

เพื่อความเป็นระเบียบเรียบร้อยและป้องกันข้อผิดพลาดในการแสดงผลบนหน้าจอ กรุณาเตรียมไฟล์และตั้งชื่อไฟล์ตามคำแนะนำดังต่อไปนี้ **ก่อนทำการอัปโหลด**เข้าระบบ:

### ✅ ข้อแนะนำในการตั้งชื่อไฟล์ (Best Practices)
* **ตั้งชื่อให้สั้นและสื่อความหมาย:** ควรตั้งชื่อไฟล์ให้รู้ทันทีว่าเป็นเอกสารอะไร เช่น `IDCard_John.pdf`, `Company_Cert_2023.pdf` หรือ `งบการเงิน_2566.xlsx`
* **หลีกเลี่ยงอักขระพิเศษ:** ไม่ควรใช้สัญลักษณ์พิเศษในชื่อไฟล์ เช่น `\ / : * ? " < > |` เพราะอาจทำให้ระบบปฏิบัติการบางชนิดอ่านไฟล์ไม่ได้
* **ใช้ภาษาไทยหรืออังกฤษได้:** ระบบรองรับการตั้งชื่อไฟล์ทั้งภาษาไทยและภาษาอังกฤษ (ระบบจะจัดการเรื่อง Encoding ให้อัตโนมัติ)
* **ขนาดและนามสกุลไฟล์:** ตรวจสอบให้แน่ใจว่าไฟล์ที่อัปโหลดเป็นนามสกุลที่ระบบรองรับ (เช่น `.pdf`, `.jpg`, `.png`, `.xlsx`)

### ❌ สิ่งที่ควรหลีกเลี่ยง
* ไม่ควรตั้งชื่อไฟล์ยาวเกินไป (เช่น พิมพ์ข้อความอธิบายยาวๆ ลงไปในชื่อไฟล์)
* ไม่ควรเว้นวรรคมากเกินความจำเป็น (แนะนำให้ใช้เครื่องหมายขีดล่าง `_` แทนการเว้นวรรค เช่น `Bank_Statement.pdf`)

> **หมายเหตุ:** ชื่อไฟล์ที่คุณตั้ง (Original Name) จะเป็นชื่อที่แสดงบนหน้าจอระบบ (UI) เพื่อให้คุณและผู้อนุมัติสามารถอ่านและเข้าใจได้ง่าย

---

## 2. กลไกการจัดเก็บของระบบ (System Storage & Security Mechanism)

เพื่อความปลอดภัยระดับองค์กร (Enterprise Security) และการตรวจสอบย้อนหลัง (Auditing) เมื่อผู้ใช้งานอัปโหลดไฟล์เข้ามาในระบบ ระบบเบื้องหลัง (Backend) จะ **ไม่ทำการบันทึกไฟล์ด้วยชื่อดั้งเดิมเดี่ยวๆ** แต่จะใช้ "กลไกการเปลี่ยนชื่อไฟล์อัตโนมัติแบบปลอดภัย" (Secure Contextual File Naming Strategy)

### โครงสร้างชื่อไฟล์บนเซิร์ฟเวอร์ (Physical File Naming Convention)
เมื่อไฟล์ถูกย้ายเข้าสู่แฟ้มจัดเก็บถาวร (`customers/`) ระบบจะเปลี่ยนชื่อไฟล์ (Physical File Name) เป็นรูปแบบดังนี้:

**`[รหัสลูกค้า]_[ชื่อไฟล์เดิมที่ตัดนามสกุลออก]_[ปีเดือนวัน_ชั่วโมงนาทีวินาที]_[มิลลิวินาที].[นามสกุลไฟล์]`**

**ตัวอย่าง:**
* รหัสลูกค้า: `01013AY`
* ผู้ใช้ตั้งชื่อไฟล์มาว่า: `Scan_001.pdf`
* เวลาที่อัปโหลด: `25 ตุลาคม 2023 เวลา 14:30:00 น. (123 มิลลิวินาที)`
* **ชื่อไฟล์ที่ถูกจัดเก็บจริงบนเซิร์ฟเวอร์:** `01013AY_Scan_001_20231025_143000_123.pdf`

### ทำไมระบบถึงใช้กลไกนี้? (Why Contextual Naming?)
1. **ป้องกันไฟล์ทับซ้อน (Collision Prevention):** การใส่ Timestamp ระดับมิลลิวินาที ทำให้มั่นใจได้ 100% ว่าหากผู้ใช้อัปโหลดไฟล์ชื่อซ้ำกัน (เช่น `untitled.pdf` หรือ `Scan_001.pdf` หลายๆ ครั้งในคำขอเดียวกัน) ไฟล์จะไม่ถูกเขียนทับ (Overwrite)
2. **การตรวจสอบย้อนหลัง (Audit-Friendly):** ผู้ดูแลระบบ (Admin) หรือ Auditor ที่เข้ามาดูไฟล์ในเซิร์ฟเวอร์ (Air-gapped server) สามารถรู้ได้ทันทีว่าไฟล์นี้เป็นของลูกค้าคนไหน และอัปโหลดเมื่อไหร่ โดยไม่ต้องเปิดดูฐานข้อมูล (Database)
3. **ความปลอดภัยของการดาวน์โหลด (Secure Download):** เมื่อผู้ใช้คลิกปุ่ม **"ดาวน์โหลด"** (Download) บนหน้าเว็บ ระบบจะบังคับให้เบราว์เซอร์ดาวน์โหลดไฟล์นั้นมาเป็น **ชื่อเต็มที่ปลอดภัย (Secure Name)** เสมอ เพื่อให้ไฟล์ที่โหลดออกไปมีความชัดเจนและตรวจสอบได้ (เช่น ได้ไฟล์ `01013AY_Scan_001_...pdf` ลงเครื่อง)

### การแสดงผลบนหน้าจอ (UI Display)
แม้ไฟล์จริงบนเซิร์ฟเวอร์จะชื่อยาว แต่เพื่อประสบการณ์การใช้งานที่ดี (UX) ฐานข้อมูล (`CreditRequestAttachments`) จะยังคงเก็บชื่อดั้งเดิม (`original_name`) ไว้ด้วย ส่งผลให้บนหน้าจอระบบ (UI) ผู้ใช้จะยังคงเห็นชื่อสั้นๆ สวยงามตามที่ตั้งไว้ตั้งแต่แรก (เช่น `Scan_001.pdf`) ไม่สร้างความสับสนระหว่างการพิจารณาคำขอ
### กลไกการค้นหาไฟล์เมื่อเกิดข้อผิดพลาด (File Resolution Fallback)

ในบางกรณีที่ระบบเก่า หรือการย้ายข้อมูล ทำให้โครงสร้างโฟลเดอร์ของรหัสคำขอ (Transaction ID) ไม่ตรงกับที่บันทึกไว้ในฐานข้อมูล (เช่น ฐานข้อมูลจำว่าไฟล์อยู่ในโฟลเดอร์ `10KKCA2604_01` แต่โฟลเดอร์จริงถูกสร้างเป็น `10KKCA2604_001`) ระบบเบื้องหลังได้มีการติดตั้งเครื่องมือ **File Resolver** ซึ่งมีกลไกการทำงานดังนี้:

1. **Exact Match:** ระบบจะพยายามค้นหาไฟล์จาก Path ตรงๆ ที่บันทึกในฐานข้อมูลก่อน โดยจะลองหาทั้งในโฟลเดอร์ `UPLOAD_BASE`, `uploads/`, และ `customers/`
2. **Loose Directory Matching:** หากไม่พบไฟล์ ระบบจะทำการดึงรหัสคำขอหลัก (เช่น `10KKCA2604`) และหมายเลขลำดับ (Running Number) จาก Path ในฐานข้อมูล จากนั้นนำไปตรวจสอบกับโฟลเดอร์จริงในระบบ หากพบโฟลเดอร์ที่มีรหัสคำขอหลักตรงกัน และมีหมายเลขลำดับที่มีค่าทางคณิตศาสตร์เท่ากัน (เช่น `_01` มีค่าเท่ากับ `_001`) ระบบจะดึงไฟล์จากโฟลเดอร์นั้นแทนอัตโนมัติ ทำให้ผู้ใช้ยังสามารถดาวน์โหลดหรือเปิดดูไฟล์ได้ตามปกติ
