# คู่มือการนำเสนอและตรวจสอบระบบ (User Verification Script)

เอกสารนี้เป็นคู่มือสำหรับใช้ในระหว่างการประชุมกับผู้ใช้งาน (User) เพื่อตรวจสอบความถูกต้องของระบบสร้างคำขอเครดิต โดยใช้งานร่วมกับ `FIELD_INVENTORY.csv` (Checklist)

---

## 1. การเตรียมตัวก่อนประชุม (Preparation)

1. **เตรียมไฟล์ Checklist:**
   - นำไฟล์ `FIELD_INVENTORY.csv` ไปเปิดใน Google Sheets หรือ Excel
   - แปลงคอลัมน์ A (ตรวจสอบ) ให้เป็น Checkbox (Insert > Checkbox) เพื่อให้ติ๊กง่ายๆ
2. **เตรียมระบบ (Environment):**
   - รันระบบในเครื่อง (Localhost) ให้พร้อมใช้งาน
   - เตรียมไฟล์ตัวอย่างสำหรับอัปโหลด (รูปภาพ, PDF) ไว้บนหน้า Desktop ให้หาง่ายๆ
   - ทดสอบการล็อกอิน (ถ้ามี) หรือเข้าหน้า `/create-credit-request` รอไว้

---

## 2. ขั้นตอนการนำเสนอ (Meeting Flow)

### ขั้นตอนที่ 1: แนะนำภาพรวม (Introduction)
* **พูด:** "วันนี้เราจะมาตรวจสอบข้อมูลในหน้า 'สร้างคำขอเครดิต' ว่าฟิลด์ต่างๆ ที่ระบบมีอยู่นั้น ครบถ้วนและถูกต้องตามที่พี่ต้องการหรือไม่ครับ โดยเราจะไล่เช็คกันไปทีละแท็บครับ"

### ขั้นตอนที่ 2: ไล่ตรวจสอบทีละแท็บ (Walkthrough)

**เริ่มจากแท็บ: ข้อมูลคำขอ (Request Info)**
1. **เปิดหน้าจอ:** แสดงแท็บ "ข้อมูลคำขอ" บนหน้าจอ
2. **ชี้แจง:** "เริ่มจากส่วนแรก เอกสารแนบครับ ระบบบังคับ 'เอกสารขอเปิดเครดิต'..."
3. **สาธิต (Demo):**
   - **กรณีบังคับ (Mandatory):** ลองกดปุ่ม **"ส่งคำขอ"** (Submit) *โดยยังไม่แนบไฟล์* เพื่อให้ User เห็น Alert เตือน
   - **พูด:** "พี่จะเห็นว่าถ้าไม่แนบไฟล์นี้ ระบบจะไม่ให้ส่งครับ ถือว่าถูกต้องไหมครับ?"
4. **บันทึกผล (Checklist):**
   - ถ้า User บอก "OK" -> **ติ๊กถูก** ใน Google Sheets ช่อง "ตรวจสอบ"
   - ถ้า User บอก "ไม่จำเป็น" หรือ "ต้องแก้" -> **จดบันทึก** ในช่อง "หมายเหตุ" (Notes)

*ทำซ้ำแบบนี้กับทุก Section (ข้อมูลทั่วไป, ที่อยู่ร้านค้า/บริษัท, ที่อยู่อาศัย, เอกสารการเงิน)*

---

### ขั้นตอนที่ 3: เทคนิคการถามเพื่อยืนยัน (Verification Questions)

อย่าถามแค่ว่า "ถูกไหมครับ?" แต่ให้ถามเจาะจง:

* **สำหรับฟิลด์ Credit Term:**
  * "ตอนนี้ระบบแยก Credit Term ออกเป็น 3 กลุ่มสินค้า (กระจก, อลูมิเนียม, ยิปซั่ม) เพื่อให้ระบุได้ละเอียดขึ้น แบบนี้ถูกต้องตามต้องการไหมครับ?"
* **สำหรับฟิลด์ที่มีดอกจัน (*):**
  * "ฟิลด์ 'เบอร์โทรศัพท์' ตอนนี้ระบบบังคับต้องกรอก ถ้าไม่มีเบอร์ ระบบจะขึ้นตัวแดง พี่โอเคกับเงื่อนไขนี้ไหมครับ?"
* **สำหรับฟิลด์ที่ไม่มีดอกจัน:**
  * "ช่อง 'แผนก' ตอนนี้ปล่อยว่างได้ พี่ต้องการให้บังคับกรอกไหมครับ?"
* **สำหรับไฟล์แนบ:**
  * "เอกสาร 'Bank Guarantee' ตอนนี้เป็นแบบเลือกแนบได้ (Optional) ไม่บังคับ ถูกต้องนะครับ?"

---

### ขั้นตอนที่ 4: สรุปและจบการประชุม (Conclusion)

1. **รีวิวสิ่งที่ต้องแก้ไข (Gap Analysis):**
   - กรอง Google Sheets ดูเฉพาะข้อที่ **ไม่ได้ติ๊กถูก** หรือมี **หมายเหตุ**
   - สรุปให้ User ฟัง: "สรุปสิ่งที่ต้องแก้มี 3 จุดนะครับ คือ 1... 2... 3..."
2. **ขอคำยืนยัน (Sign-off):**
   - "ถ้าแก้ 3 จุดนี้เสร็จ ถือว่าหน้าจอนี้ผ่านใช้งานจริงได้เลยใช่ไหมครับ?"

---

## Tips สำหรับการ Demo
* **อย่ากรอกข้อมูลถูกทั้งหมดทันที:** ให้ลองกรอกผิด หรือเว้นว่าง เพื่อโชว์ Validation Error สีแดง ให้ User มั่นใจว่าระบบช่วยดักข้อมูลให้
* **เตรียมคำตอบเรื่องการบังคับ:** ถ้าระบบบังคับแค่ "เตือนหน้าบ้าน" (ขอบแดง) แต่ User อยากให้ "กดส่งไม่ได้เลย" ให้จดไว้ว่าเป็น Change Request (CR)
