# แผนการทดสอบระบบ (UAT Plan) - ระบบขออนุมัติเครดิต

เอกสารฉบับนี้จัดทำขึ้นเพื่อใช้ประกอบการทดสอบระบบก่อนการอบรม (Training Session) โดยมุ่งเน้นที่หน้าจอ **สร้างคำขอใหม่ (/create-credit-request)** และหน้า **คำขอรอดำเนินการ (/pending-requests)** ครอบคลุมผู้ใช้งาน 2 บทบาทหลัก คือ Maker (ผู้สร้างคำขอ/ผู้จัดการสาขา) และ Approver (ผู้อนุมัติ/ผู้จัดการภาคขึ้นไป)

---

## 🛠️ ข้อกำหนดเบื้องต้น (Prerequisites)
1. ติดตั้งและเปิดใช้งาน Backend และ Database เรียบร้อยแล้ว
2. สามารถเข้าสู่ระบบผ่านหน้าจอหรือมี User ทดสอบสำหรับ Maker และ Approver
3. เตรียมข้อมูลลูกค้าทดสอบ (รหัสลูกค้า หรือ ชื่อบริษัท) สำหรับการค้นหาและสร้างคำขอใหม่

---

## 🧑‍💻 1. บทบาท: Maker (ผู้จัดการสาขา / ผู้สร้างคำขอ)

### 📝 Test Case 1.1: การแสดงผลและติดตามคำขอ (Track Requests)
**จุดประสงค์:** เพื่อทดสอบว่า Maker สามารถดูรายการคำขอที่ตนเองสร้างและส่งไปแล้ว เพื่อติดตามสถานะ (Track Status) ได้ในโหมดอ่านอย่างเดียว (Read-Only)
**ขั้นตอนการทดสอบ:**
1. เข้าสู่ระบบด้วยสิทธิ์ **Maker**
2. ไปที่หน้า **"คำขอรอดำเนินการ"** (`/pending-requests`)
3. สังเกตที่แท็บเมนูด้านซ้ายบน แท็บแรกจะต้องเปลี่ยนชื่อจาก "รออนุมัติ" เป็น **"ติดตามคำขอ"**
4. ไปที่เมนู **"สร้างคำขอใหม่"** (`/create-credit-request`) และสร้างคำขอโดยใช้ **"ลูกค้าระยะทดสอบที่มีข้อมูลทางการเงินในระบบแล้ว"**
5. กรอกข้อมูลให้ครบถ้วนและกด **"ส่งคำขอ" (Submit)** เพื่อให้คำขอเปลี่ยนสถานะจาก Draft ไปเป็น Opened (หรือสถานะถัดไป)
6. กลับมาที่หน้า **"คำขอรอดำเนินการ"** (`/pending-requests`) อีกครั้ง ตรวจสอบในแท็บ "ติดตามคำขอ"
7. คลิกที่รายการคำขอที่เพิ่งส่งไป
**ผลลัพธ์ที่คาดหวัง:**
- คำขอที่เพิ่งส่งไป (เช่น สถานะ Opened, RegionalSubmitted, SalesSubmitted) จะต้องปรากฏอยู่ในแท็บ **"ติดตามคำขอ"**
- ระบบจะต้องแสดงรายละเอียดแบบ **Read-Only** (ช่องกรอกข้อมูลเป็นสีเทาและไม่สามารถแก้ไขได้)
- **ต้องไม่มีปุ่ม อนุมัติ/ไม่อนุมัติ (Approve/Reject)** ปรากฏที่ Action Bar ด้านล่าง

### 📝 Test Case 1.2: การแสดงผล Request Timeline (ติดตามความคืบหน้า)
**จุดประสงค์:** เพื่อทดสอบว่า Maker สามารถเห็นภาพรวมประวัติการพิจารณาเป็นแบบ Timeline จากบนลงล่างได้อย่างถูกต้อง
**ขั้นตอนการทดสอบ:**
1. เข้าสู่ระบบด้วยสิทธิ์ **Maker**
2. ไปที่หน้า **"คำขอรอดำเนินการ"** (`/pending-requests`) และเปิดคำขอที่ส่งไปแล้ว (เช่น สถานะ Opened หรือ RegionalSubmitted)
3. เลื่อนลงมาที่ส่วน **"บันทึกการพิจารณา"** (Credit Review Section) ด้านล่างสุด
4. สังเกต **Request Timeline** ที่แสดงผลอยู่
**ผลลัพธ์ที่คาดหวัง:**
- ระบบจะต้องแสดง Timeline ตามมาตรฐาน 5 ขั้นตอน (ผู้จัดการสาขา -> ผู้จัดการภาค -> ผู้จัดการฝ่ายขาย -> เจ้าหน้าที่ฝ่ายการเงิน -> กรรมการเครดิต) โดยเรียงลำดับจากบนลงล่าง
- ขั้นตอนที่ดำเนินการแล้ว (เช่น ผู้จัดการสาขา) จะต้องเป็นสีน้ำเงิน (Completed) พร้อมแสดงวันที่ เวลา และความคิดเห็น (Comment) อย่างถูกต้อง
- ขั้นตอนที่รอการดำเนินการในอนาคต จะต้องแสดงข้อความ "รอการพิจารณา" (Pending) และเป็นสีเทา
- *กรณีเพิ่มเติม (Rejected):* หากคำขอนั้นถูกปฏิเสธ (Rejected) Timeline จะต้องแสดงขั้นตอนที่ถูกปฏิเสธเป็นสีแดง (เครื่องหมายกากบาท) พร้อมข้อความปฏิเสธ และซ่อนขั้นตอนอื่นๆ ที่เหลืออยู่ในอนาคตทั้งหมด

### 📝 Test Case 1.3: การสร้างคำขอและบันทึกเป็นแบบร่าง (Save Draft)
**จุดประสงค์:** เพื่อทดสอบว่า Maker สามารถกรอกข้อมูลบางส่วนและบันทึกเป็นแบบร่าง (Draft) ได้ โดยข้อมูลไม่สูญหาย
**ขั้นตอนการทดสอบ:**
1. เข้าสู่ระบบด้วยสิทธิ์ **Maker**
2. ไปที่เมนู **"สร้างคำขอใหม่"** (`/create-credit-request`)
3. ในส่วน **"ค้นหาลูกค้า"** ให้พิมพ์ รหัสลูกค้า หรือ ชื่อบริษัท จากนั้นกดเลือกจากรายการค้นหา
4. กรอกข้อมูลบางส่วนในแท็บแรก (เช่น ข้อมูลทั่วไป)
5. กดปุ่ม **"บันทึกร่าง"** หรือฟังก์ชันเซฟสำหรับฉบับร่าง
6. รีเฟรชหน้าจอ (Refresh) หรือกลับไปที่หน้าหลัก แล้วกลับมาที่ **"สร้างคำขอใหม่"** (`/create-credit-request`)
7. ค้นหาลูกค้าคนเดิมอีกครั้งในแผงค้นหาด้านซ้าย
**ผลลัพธ์ที่คาดหวัง:**
- **สำคัญ:** รายการที่บันทึกเป็นแบบร่างจะ **ไม่ไปปรากฏ** ในหน้า "คำขอรอดำเนินการ" (`/pending-requests`) เพื่อแยกส่วนการทำงานที่ยังไม่เสร็จสิ้นออกจากคำขอที่รออนุมัติ
- เมื่อค้นหาและโหลดข้อมูลลูกค้าคนเดิม ข้อมูลที่กรอกค้างไว้ในแบบร่าง (Draft) จะต้องถูกโหลดกลับมาครบถ้วนเพื่อดำเนินการต่อ
- ปุ่มส่งคำขอและบันทึกการพิจารณาจะใช้งานได้ตามปกติเมื่อเข้าสู่แท็บสุดท้ายหรือมุมมองแสดงข้อมูลทั้งหมด

### 📊 Test Case 1.4: การจัดการลูกค้าในกรณี "ไม่มีงบการเงิน" (No Financial Data)
**จุดประสงค์:** เพื่อทดสอบการรับมือกับลูกค้านิติบุคคลที่ไม่มีข้อมูลทางการเงินในระบบ DBD
**ขั้นตอนการทดสอบ:**
1. สร้างคำขอใหม่ และเลือกแท็บ **"รายการเดินบัญชี"** (Store Statement / Financials)
2. หากเป็นลูกค้าบริษัทที่มีเลขทะเบียนนิติบุคคล แต่ระบบไม่สามารถดึงข้อมูลได้ ให้สังเกตสถานะการดึงข้อมูล
3. ติ๊กเครื่องหมายถูกที่ช่อง **"ลูกค้าไม่มีงบการเงิน"**
4. (หากมี) ลองแนบเอกสารเพิ่มเติม
**ผลลัพธ์ที่คาดหวัง:**
- แบดจ์สถานะแสดงข้อความเตือน หรือเครื่องหมายเช็คบ็อกซ์ "ลูกค้าไม่มีงบการเงิน" สามารถถูกเลือกได้
- ระบบยอมรับการตั้งค่านี้ และอนุญาตให้ไปทำรายการแท็บถัดไปได้ตามปกติ โดยไม่บังคับแจ้งเตือนเรื่องคะแนนทางการเงินจาก DBD

### 🚀 Test Case 1.3: การส่งคำขอที่สมบูรณ์ (Submit Request)
**จุดประสงค์:** เพื่อทดสอบกระบวนการส่งคำขออย่างเป็นทางการของ Maker
**ขั้นตอนการทดสอบ:**
1. กรอกข้อมูลให้ครบถ้วนทุกแท็บ รวมถึงเอกสารบังคับ (มีเครื่องหมาย *)
2. ในแท็บสุดท้าย หรือมุมมองรวม (แสดงข้อมูลทั้งหมด) ตรวจสอบปุ่มการกระทำ (Action Buttons)
3. พิมพ์ความเห็นในการขออนุมัติในช่อง **"ความคิดเห็น"**
4. กดปุ่ม **"ส่งคำขอ"**
5. กดยืนยันในกล่องข้อความ (Popup) ว่าต้องการยืนยันการทำรายการ
**ผลลัพธ์ที่คาดหวัง:**
- มีข้อความแจ้งเตือน "คำขอถูกส่งเรียบร้อยแล้ว"
- หน้าจอทั้งหมดจะถูกล็อคกลายเป็นโหมด **อ่านอย่างเดียว (Read Only)** ปุ่ม Action หรือกล่องความคิดเห็นจะถูกซ่อน
- คำขอจะเปลี่ยนสถานะจาก "ร่าง" เป็น **"รออนุมัติ"**

## 🛡️ 2. บทบาท: Approver (ผู้จัดการภาค / ฝ่ายสินเชื่อ)

### 🔍 Test Case 2.1: การค้นหาและตรวจสอบคำขอบนหน้า Dashboard
**จุดประสงค์:** เพื่อทดสอบว่า Approver เห็นคำขอที่รอดำเนินการถูกต้องและสามารถดูข้อมูลได้
**ขั้นตอนการทดสอบ:**
1. เข้าสู่ระบบด้วยสิทธิ์ **Approver** (เช่น ผู้จัดการภาค)
2. ไปที่เมนู **"คำขอรอดำเนินการ"** (`/pending-requests`)
3. ในแถบด้านซ้าย (Sidebar) ลองใช้ช่อง **"ค้นหาด้วย รหัสลูกค้า ชื่อ..."** พิมพ์หาคำขอที่เพิ่งส่งจาก Maker
4. คลิกเลือกคำขอนั้น
**ผลลัพธ์ที่คาดหวัง:**
- คำขอที่เพิ่งสร้างและอยู่ในสถานะไม่สิ้นสุด (non-final) จะแสดงในรายการตามสิทธิ์ของบทบาท
- สำหรับบทบาท approver-chain (`ผู้พิจารณาฝ่ายขาย`, `ผู้ตรวจสอบเอกสาร`, `ผู้อนุมัติ (วงเงินต่ำกว่าเกณฑ์)`, `ผู้อนุมัติ (วงเงินสูงกว่าเกณฑ์)`) ต้องเห็นรายการ non-final ได้กว้างขึ้น ไม่จำกัดเฉพาะสถานะที่กำลังรอตนเองเท่านั้น
- เมื่อคลิกดูคำขอที่ **ไม่ใช่สถานะรับผิดชอบของบทบาทนั้น** ข้อมูลต้องเป็นโหมด **อ่านอย่างเดียว (Read-only)**
- เมื่อคลิกดูคำขอที่ **เป็นสถานะรับผิดชอบของบทบาทนั้น** ต้องสามารถดำเนินการ Workflow ตามสิทธิ์ได้
- สามารถสลับแท็บเพื่อดูเอกสาร, ประวัติ และคะแนนเครดิตได้

### 📄 Test Case 2.2: การดูเอกสารทั้งหมด (View All Documents)
**จุดประสงค์:** เพื่อทดสอบระบบแสดงตัวอย่างเอกสารทั้งหมด (Split-Pane Modal) ที่ช่วยให้ผู้อนุมัติสามารถตรวจสอบเอกสารประกอบคำขอได้อย่างรวดเร็ว
**ขั้นตอนการทดสอบ:**
1. เข้าสู่ระบบด้วยสิทธิ์ **Approver** (เช่น ผู้จัดการภาค)
2. ไปที่เมนู **"คำขอรอดำเนินการ"** (`/pending-requests`)
3. คลิกเลือกคำขอที่มีการแนบเอกสารเรียบร้อยแล้ว (เช่น รหัสลูกค้าทดสอบที่มีงบการเงินหรือรูปถ่าย)
4. เลื่อนลงมาที่ส่วน **"สถานะเอกสาร"** ในหน้าแสดงรายละเอียดคำขอ
5. คลิกปุ่ม **"ดูเอกสารทั้งหมด"** (ปุ่มสีฟ้าด้านขวาของจำนวนรายการ)
6. สังเกตหน้าต่าง Modal ที่แสดงขึ้นมาแบบแยกส่วน (Split-Pane)
7. ในแถบเมนูด้านซ้าย ให้คลิกเลือกเอกสารต่างๆ ทั้งในกลุ่ม "เอกสารหลัก" และ "เอกสารอื่นๆ"
**ผลลัพธ์ที่คาดหวัง:**
- เมื่อคลิกปุ่ม ระบบจะต้องแสดง Modal ขนาดใหญ่ขึ้นมา
- แถบด้านซ้ายจะต้องแสดงรายการเอกสารทั้งหมด (ทั้งที่มีไฟล์และยังไม่แนบ) และจัดกลุ่มอย่างชัดเจน (เอกสารหลัก / เอกสารอื่นๆ)
- ข้อความชื่อเอกสารและสถานะ (เช่น แนบแล้ว, ยังไม่แนบ) ในแถบด้านซ้าย จะต้องชิดซ้าย (Left-aligned)
- เมื่อคลิกเอกสารที่มีสถานะ "แนบแล้ว" หน้าต่างด้านขวาจะต้องแสดงตัวอย่างเอกสารได้ทันที (รองรับ PDF และ รูปภาพ)
- ในกรณีที่ไฟล์ไม่รองรับการแสดงผลผ่านเบราว์เซอร์ (เช่น Excel) หน้าต่างด้านขวาจะต้องแสดงข้อความแจ้งเตือนและมีปุ่มให้ **"ดาวน์โหลดไฟล์"** แทน
- การกดปุ่มกากบาท (X) หรือคลิกพื้นที่ว่างนอก Modal จะเป็นการปิดหน้าต่างและกลับสู่หน้า Dashboard ตามปกติ

### ✅ Test Case 2.3: การพิจารณาอนุมัติ (Approve)
**จุดประสงค์:** เพื่อทดสอบการทำงานของปุ่ม Workflow Approval
**ขั้นตอนการทดสอบ:**
1. เลือกคำขอที่สถานะตรงกับบทบาทที่กำลังทดสอบ (เช่น ผู้พิจารณาฝ่ายขาย -> `RegionalSubmitted`, ผู้ตรวจสอบเอกสาร -> `SalesSubmitted`)
2. ในหน้าของคำขอนั้น เลื่อนลงไปที่ส่วน **"บันทึกการพิจารณา"** (Credit Review Section) หรือแถบ **Workflow Action Bar**
3. ยืนยันว่าปุ่ม Workflow ปรากฏและช่องความคิดเห็นสามารถแก้ไขได้
4. พิมพ์ข้อความในช่อง **"ความคิดเห็น"** (เช่น "อนุมัติตามเสนอ")
5. กดปุ่ม **"อนุมัติ"**
6. กดยืนยันการทำรายการ
**ผลลัพธ์ที่คาดหวัง:**
- ระบบบันทึกการอนุมัติเรียบร้อย และเปลี่ยนสถานะคำขอเป็นขั้นตอนถัดไปหรืออนุมัติแล้ว
- รายการนั้นจะหายไปจาก Dashboard "รออนุมัติ" ของตนเอง (หรือถูกจัดกลุ่มในหมวดอื่น)
- ประวัติความเห็นในส่วนล่างจะปรากฏชื่อและข้อความที่พิมพ์ไป
- ถ้าเปิดคำขอที่ไม่อยู่ในสถานะรับผิดชอบของบทบาท ปุ่ม Workflow ต้องไม่ปรากฏหรืออยู่ในสภาพใช้งานไม่ได้ และฟอร์มต้องอ่านอย่างเดียว

### ❌ Test Case 2.3: การพิจารณาไม่อนุมัติ (Reject) (ทดสอบเพิ่มเติม - เสริม)
**จุดประสงค์:** เพื่อทดสอบกระบวนการปฏิเสธคำขอ
**ขั้นตอนการทดสอบ:**
1. เปิดคำขอรอดำเนินการขึ้นมา 1 รายการ
2. พิมพ์ความเห็นในช่อง "ความคิดเห็น" (เช่น "เอกสารไม่ครบ")
3. กดปุ่ม **"ไม่อนุมัติ"**
4. กดยืนยันการทำรายการ
**ผลลัพธ์ที่คาดหวัง:**
- สถานะคำขอเปลี่ยนเป็นไม่อนุมัติ
- คำขอนั้นหายไปจากรายการรอพิจารณา และจะกลับไปแสดงให้ Maker เห็น เพื่อที่ Maker จะสามารถใช้ปุ่ม "สร้างคำขอใหม่ (แก้ไข)" (Request Revision) ได้

---
*หมายเหตุสำหรับผู้ดำเนินการอบรม:*
- ก่อนทดสอบ ควรมั่นใจว่าไม่ได้เปิดหน้าจอค้างไว้นานเกินไป เพื่อป้องกันเซสชั่นหมดอายุ
- สังเกตการแสดงผลของ UI ที่เป็นฟิลด์ปิดการแก้ไข (Disabled) จะต้องมีพื้นหลังสีขาว ตัวอักษรสีดำ และไม่มีลูกศร Dropdown ในกรณีที่เป็นฟิลด์ว่าง
### 🔄 Test Case 2.4: การล้างข้อมูลคำขอเมื่อเข้าสู่หน้า Pending Requests (State Reset)
**จุดประสงค์:** เพื่อทดสอบว่าเมื่อเข้าสู่หน้า "คำขอรอดำเนินการ" (`/pending-requests`) ระบบจะเริ่มต้นด้วยหน้าจอที่ไม่มีการเลือกคำขอค้างไว้
**ขั้นตอนการทดสอบ:**
1. เข้าสู่ระบบด้วยสิทธิ์ใดๆ (เช่น Maker หรือ Approver)
2. ไปที่หน้า **"สร้างคำขอใหม่"** (`/create-credit-request`)
3. ค้นหาลูกค้าและคลิกดูประวัติ หรือกรอกข้อมูลบางส่วนจนปรากฏข้อมูลลูกค้าในหน้าจอ
4. สลับไปที่เมนู **"คำขอรอดำเนินการ"** (`/pending-requests`) ทันที
5. สังเกตหน้าจอตรงกลาง (Content Area)
**ผลลัพธ์ที่คาดหวัง:**
- หน้าจอตรงกลางจะต้องแสดงข้อความ "เลือกรายการทางซ้ายเพื่อดูรายละเอียด" (Placeholder state)
- ข้อมูลลูกค้าหรือคำขอที่เพิ่งดูจากหน้าก่อนหน้านี้จะต้องไม่ปรากฏขึ้นมาค้างไว้
- แถบด้านซ้าย (Sidebar) แสดงรายการตามปกติ และต้องไม่ถูกไฮไลต์ (Active) จนกว่าผู้ใช้จะคลิกเลือกเอง
