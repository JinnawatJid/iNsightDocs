## 2.5 สถาปัตยกรรมการตั้งค่าระบบด้วยรูปแบบ JSON (JSON-Based Configuration)

ในการพัฒนาระบบ CreditInsight ผู้จัดทำได้ออกแบบสถาปัตยกรรมของระบบให้มีความยืดหยุ่น โดยแยกส่วนที่เป็นตรรกะทางธุรกิจ (Business Logic) และกระบวนการทำงาน (Workflow) ออกจากโค้ดหลักของโปรแกรม (Hardcoded Logic) ด้วยการใช้ไฟล์หรือข้อมูลในรูปแบบ JSON (JavaScript Object Notation) เป็นศูนย์กลางในการตั้งค่าระบบ โดยสามารถแบ่งออกเป็น 2 ส่วนหลัก ได้แก่

### 2.5.1 แนวคิด JSON-Based Workflow Configuration แทนการใช้ PAIS
ในการพัฒนาระบบการอนุมัติเครดิต ผู้จัดทำได้พิจารณาการนำแนวคิด Process-Aware Information Systems (PAIS) มาประยุกต์ใช้ในเบื้องต้น อย่างไรก็ตาม การนำ PAIS มาใช้อย่างเต็มรูปแบบนั้นต้องการโครงสร้างฐานข้อมูลที่ซับซ้อน เช่น ตารางสำหรับบันทึกสถานะกระบวนการ ตารางผู้อนุมัติ ตารางสิทธิ์การเข้าถึง และตารางลำดับขั้นตอน ซึ่งต้องมีการคำนวณและ JOIN ข้อมูลหลายตารางในทุกการประมวลผล ส่งผลให้ระบบมีความซับซ้อนสูงและยากต่อการบำรุงรักษาในระยะยาว

ผู้จัดทำจึงเลือกใช้แนวทาง **JSON-Based Workflow Configuration** แทน โดยจัดเก็บโครงสร้างสถานะของกระบวนการอนุมัติ (Workflow States) เงื่อนไขการเปลี่ยนสถานะ (Allowed Transitions) และสิทธิ์ตามบทบาท (Role-Based Permissions) ไว้ในฐานข้อมูลรูปแบบ JSON (`WORKFLOW_CONFIG`) แนวทางนี้ช่วยลดความซับซ้อนของฐานข้อมูลเชิงสัมพันธ์ลงได้อย่างมาก แต่ยังคงความสามารถในการปรับเปลี่ยนกระบวนการทำงาน (Workflow) หรือแก้ไขบทบาทผู้อนุมัติได้แบบพลวัต (Dynamic) ผ่านการแก้ไขไฟล์ JSON โดยไม่ต้องแก้ไขโค้ดโปรแกรมหรือปรับโครงสร้างฐานข้อมูลใหม่

### 2.5.2 แนวคิด JSON-Based Scorecard Configuration
สำหรับตรรกะในการประเมินความเสี่ยงและพิจารณาวงเงินเครดิต ระบบได้ใช้แนวทาง **JSON-Based Scorecard Configuration** โดยจัดเก็บเกณฑ์การประเมินเครดิตไว้ในรูปแบบไฟล์ JSON (เช่น `credit_scorecard_v1.json`) ซึ่งทำหน้าที่เป็น Scorecard กลางของระบบ

**หลักการทำงานของ JSON Scorecard**
ไฟล์ JSON Scorecard ประกอบด้วยโครงสร้างหลัก 3 ส่วน ได้แก่
1. **ส่วนกำหนดตัวแปรและน้ำหนัก (Variables & Weights):** ระบุว่าข้อมูลใดบ้างที่นำมาคำนวณคะแนนและมีค่าน้ำหนัก (Weight) เท่าใด
2. **ส่วนกำหนดเกณฑ์การแปลงคะแนน (Score Mapping & Thresholds):** ระบุช่วงขอบเขตของค่าต่างๆ เพื่อให้คะแนน และการแปลงคะแนนรวมเป็นเกรด (Risk Grade)
3. **ส่วนตารางวงเงินที่แนะนำ (Credit Limit Table):** ระบุวงเงินเครดิตที่เหมาะสมสำหรับลูกค้าในแต่ละเกรดและแต่ละขนาดธุรกิจ (Business Size)

เมื่อระบบได้รับข้อมูลลูกค้า เครื่องมือคำนวณ (Scoring Engine) จะอ่านเกณฑ์จากไฟล์ JSON และคำนวณคะแนนตามโครงสร้างที่กำหนดไว้ ผลลัพธ์ที่ได้คือคะแนนรวม เกรดความเสี่ยง และวงเงินที่แนะนำ เพื่อให้ผู้อนุมัติใช้ประกอบการตัดสินใจ

**ขอบเขตการปรับแต่งและเหตุผลในการเลือกแนวทางนี้**
แนวทาง JSON Scorecard เหมาะสมกับบริบทของโครงงานนี้เนื่องจากเกณฑ์การประเมินเครดิตขององค์กรมีโครงสร้างของตัวแปรหลักที่ค่อนข้างคงที่ (เช่น ประวัติการชำระเงิน, ขนาดธุรกิจ) แต่มีความต้องการในการปรับแต่งค่าน้ำหนักหรือขอบเขตเกณฑ์บ่อยครั้ง ผู้ดูแลระบบสามารถปรับแต่งค่าต่างๆ ได้ผ่านหน้าจอการจัดการ Scorecard (Scorecard Management UI) เช่น การปรับน้ำหนักของตัวแปรแต่ละตัว การปรับช่วงเกณฑ์คะแนน และการปรับตารางวงเงินที่แนะนำ โดยข้อมูลจะถูกบันทึกและจัดการเวอร์ชัน (Versioning) ในฐานข้อมูล และมีผลบังคับใช้ทันทีโดยไม่จำเป็นต้องแก้ไขและคอมไพล์โค้ดโปรแกรมใหม่ อย่างไรก็ตาม โครงสร้างนี้มีข้อจำกัดคือการเพิ่มหรือลด "ตัวแปรใหม่" ที่ระบบไม่เคยรู้จักมาก่อน ยังคงต้องมีการพัฒนาโค้ดเพิ่มเติมเพื่อเชื่อมต่อแหล่งข้อมูล แต่สำหรับการปรับจูนโมเดล (Model Tuning) สามารถทำได้อย่างอิสระ
