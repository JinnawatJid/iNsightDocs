3.8 Functional Requirements
3.8.1 การเข้าสู่ระบบและการจัดการสิทธิ์
* FR 1.1: ระบบต้องรองรับการพิสูจน์ตัวตน เพื่อเข้าสู่ระบบ โดยผู้ใช้งาน ประกอบด้วย ผู้จัดการสาขา ผู้จัดการภูมิภาค ผู้จัดการฝ่ายขาย เจ้าหน้าที่ฝ่ายการเงิน ผู้จัดการฝ่ายการเงิน และคณะกรรมการเครดิต ต้องระบุ รหัสพนักงาน และ รหัสผ่าน ผ่านหน้าจอ Login จากระบบ SSO ขององค์กร 
* FR 1.2: ระบบต้องตรวจสอบความถูกต้องของข้อมูล และการแสดงหน้าจอหลัก พร้อมเมนูที่สอดคล้องกับบทบาทของผู้ใช้งานนั้น
   * FR 1.2.1: ผู้จัดการสาขา ต้องเห็นเมนู "สร้างคำขอ" และ "คำขอทั้งหมด"
   * FR 1.2.2: สำหรับบทบาท ผู้จัดการภูมิภาค ผู้จัดการฝ่ายขาย ผู้จัดการฝ่ายการเงิน คณะกรรมการเครดิต ต้องเห็นเมนู “ค้นหาลูกค้า” และ “คำขอทั้งหมด”
   * FR 1.2.3: เจ้าหน้าที่ฝ่ายการเงิน ต้องเห็นเมนู "ค้นหาลูกค้า" “คำขอทั้งหมด” และ “ระบบอัตโนมัติ”
   * FR 1.2.4: ผู้ดูแลระบบ ต้องเห็นเมนู “ค้นหาลูกค้า” “คำขอทั้งหมด” และ “ตั้งค่าระบบ” 
3.8.2 กระบวนการสร้างคำขอเครดิต
* FR 2.1: ระบบต้องสามารถตรวจสอบเงื่อนไขการขอเครดิตของลูกค้าก่อนที่ให้ผู้จัดการสาขา จะสามารถเลือกประเภทคำขอเครดิตได้ โดยแบ่งเป็น 5 ประเภท ได้แก่
   * เครดิตใหม่
   * เครดิตเพิ่ม
   * เปลี่ยนแปลงระยะเวลาเครดิต
   * เปลี่ยนแปลงเงื่อนไขชำระเงิน
   * เครดิตโครงการ
* FR 2.2: ระบบต้องแสดงฟอร์มอิเล็กทรอนิกส์ที่มีช่องกรอกข้อมูลแตกต่างกันตามประเภทลูกค้าและประเภทคำขอเครดิตที่ถูกเลือกในเมนูสร้างคำขอ ได้แก่
   * ฟอร์มที่เปลี่ยนแปลงตาม "ประเภทลูกค้า"
      * หัวข้อแท็บ:
         * ลูกค้านิติบุคคล: แสดงชื่อแท็บว่า "ข้อมูลบริษัท"
         * ลูกค้าบุคคลธรรมดา: แสดงชื่อแท็บว่า "ข้อมูลร้านค้า"
      * รายการเอกสารบังคับ:
         * นิติบุคคล: บังคับ หนังสือรับรองบริษัท ภ.พ.20 รูปถ่ายบริษัท
         * บุคคลธรรมดา: บังคับ รูปถ่ายหน้าร้าน รายการเดินบัญชี
   * ฟอร์มที่เปลี่ยนแปลงตาม "ประเภทคำขอ"
      * คำขอเครดิตใหม่
         * บังคับแสดงฟิลด์ "ที่มาของเครดิต" และ "ข้อมูลการติดต่อ"
         * บังคับแสดงการอัปโหลด "เอกสารแนบ" ทั้งหมด
         * บังคับแสดงฟิลด์ "การวางบิล" และ "ระยะเวลาเครดิต" แบบครบทุกกลุ่มสินค้า (กระจก อลูมิเนียม ยิปซั่ม)
      * คำขอเครดิตเพิ่ม
         * ระบบจะแสดงช่องคำนวณอัตโนมัติ "วงเงินรวมทั้งหมด" เพิ่มขึ้นมา เพื่อแสดงผลรวมระหว่างวงเงินปัจจุบันและวงเงินที่ขอเพิ่ม
      * คำขอเปลี่ยนแปลงระยะเวลาเครดิต / เปลี่ยนแปลงเงื่อนไขการชำระเงิน
         * ซ่อนช่องกรอก "วงเงินเครดิตที่ต้องการ" และเปลี่ยนเป็นแสดง "วงเงินปัจจุบัน" แบบ Disabled อ่านได้อย่างเดียว
         * ระบบจะซ่อนแท็บข้อมูลลูกค้าอื่นๆ เช่น ทะเบียนบ้าน/รูปถ่าย แล้วโชว์เฉพาะแท็บ "เงื่อนไขและคำขอ" พร้อมข้อความและฟอร์มให้กรอกเหตุผลที่ขอเปลี่ยน
      * คำขอเครดิตโครงการ:
         * ระบบจะพับแถบข้อมูลทั่วไปของลูกค้า และแสดงการ์ดเครดิตโครงการ ขึ้นมาแทน ซึ่งให้กรอกข้อมูลและเงื่อนไขโครงการ รวมถึงแสดงหน้า Phasing เพื่อคำนวณงวดงาน/การเบิกจ่าย
* FR 2.3: ระบบต้องทำการตรวจสอบข้อมูลพื้นฐานที่จำเป็น โดยบังคับกรอก หากกรอกไม่ครบถ้วนระบบจะไม่ข้ามไปขั้นตอนถัดไป ได้แก่
   * FR 2.3.1: ข้อมูลที่จำเป็นพื้นฐานในส่วนของการขอเครดิต ได้แก่
      * ชื่อผู้ติดต่อ
      * ตำแหน่งผู้ติดต่อ
      * เบอร์โทรศัพท์ผู้ติดต่อ
      * วงเงินเครดิตที่ขอ
      * ที่มาของเหตุผลการขอเครดิต
      * เงื่อนไขการวางบิล
      * วิธีชำระเงิน
      * มีเครดิตกับที่อื่นหรือไม่
      * ระยะเวลาเครดิตของแต่ละกลุ่มสินค้า
   * FR 2.3.2: ข้อมูลที่จำเป็นพื้นฐานในส่วนของลูกค้า ได้แก่
      * ชื่อบริษัท/ลูกค้า
      * ชื่อผู้มีอำนาจลงนาม
      * ตำแหน่งผู้มีอำนาจ
      * ประเภทธุรกิจ
      * สินค้าหลัก
      * ระยะเวลาดำเนินธุรกิจ
      * ความสัมพันธ์กับลูกค้ารายอื่นในบริษัท
   * FR 2.3.3: ข้อมูลที่พักอาศัยและกรรมสิทธิ์ทรัพย์สิน ได้แก่
      * ที่อยู่และเบอร์โทรศัพท์ที่พักอาศัย
      * ประเภทที่พักอาศัย
      * มูลค่าที่พักอาศัย
      * กรรมสิทธิ์ที่พักอาศัย
   * FR 2.3.4: ข้อมูลที่ตั้งร้านค้า/บริษัทและกรรมสิทธิ์ทรัพย์สิน ได้แก่
      * ที่อยู่และเบอร์โทรศัพท์ร้านค้า/บริษัท
      * ประเภทที่ทำเล/อาคาร
      * มูลค่าที่พักทำเล/อาคาร
      * กรรมสิทธิ์ทำเล/อาคาร
* FR 2.4: ระบบต้องจัดให้มีช่องกรอกข้อความ เพื่อให้ผู้จัดการสาขาสามารถระบุ เหตุผลความจำเป็นในการขอวงเงินเครดิต
* FR 2.5: ผู้จัดการสาขา ต้องสามารถแนบไฟล์ที่จำเป็น ตามประเภทลูกค้า ได้แก่
   * FR 2.5.1: กรณีลูกค้าช่าง/ร้านค้า ต้องแนบไฟล์ 5 รายการ ได้แก่
      * 1. ใบคำขอเครดิต
      * 2. สำเนาบัตรประชาชน
      * 3. สำเนาทะเบียนบ้าน
      * 4. รูปถ่ายหน้าร้าน
      * 5. รายการเดินบัญชี 
   * FR 2.5.2: กรณีนิติบุคคล ต้องแนบไฟล์ 6 รายการ ได้แก่
      * 1. ใบคำขอเครดิต
      * 2. สำเนาบัตรประชาชนกรรมการ
      * 3. สำเนาทะเบียนบ้านกรรมการ
      * 4. หนังสือรับรองบริษัท 5. เอกสารภ.พ. 20
      * 6. รูปถ่ายหน้าบริษัท
* FR 2.6: ระบบต้องสามารถบันทึกฉบับร่าง เพื่อให้ผู้สร้างเอกสารสามารถบันทึกข้อมูลและไฟล์แนบที่กรอกไว้ชั่วคราวเข้าสู่ฐานข้อมูล และสามารถกลับมาแก้ไขหรือดำเนินการต่อในภายหลังได้ โดยเอกสารจะอยู่ในสถานะ ฉบับร่าง
3.8.3 กระบวนการส่งอนุมัติคำขอ
* FR 3.1: ผู้จัดการสาขา ต้องสามารถกดปุ่ม "ส่งคำขอ" เพื่อเริ่มกระบวนการได้
* FR 3.2: เมื่อมีการกดส่งคำขอ ระบบต้องทำหน้าที่ตรวจสอบความครบถ้วนสมบูรณ์ของข้อมูล ทั้งในส่วนช่องข้อมูลบังคับและความครบถ้วนของไฟล์แนบที่บังคับ
* FR 3.3: หากตรวจสอบแล้วเป็นคำขอจากลูกค้าบริษัท/นิติบุคคล ระบบสามารถดาวน์โหลดข้อมูลจากกรมพัฒนาธุรกิจการค้า โดยอัตโนมัติ โดยใช้เลขประจำตัวผู้เสียภาษีในการดาวน์โหลด โดยจะดาวน์โหลดเอกสาร ได้แก่
   * 1. เอกสารรับรองนิติบุคคล 
   * 2. เอกสารงบดุล
   * 3. เอกสารกำไรขาดทุน
   * 4. เอกสารสัดส่วนทางการเงิน
เก็บบันทึกในระบบโดยอัตโนมัติ ในกรณีที่ระบบไม่สามารถดาวน์โหลดข้อมูลได้ ผู้จัดการสาขาจะต้องสามารถแนบเอกสารดังกล่าวได้
* FR 3.4: ระบบต้องทำการเรียกใช้งาน API เชื่อมต่อไปยังระบบแลกเปลี่ยนข้อมูลขององค์กร (UXP Systems) โดยอัตโนมัติ เพื่อดึงข้อมูล ประวัติการซื้อสินค้าย้อนหลัง 3 เดือน ของลูกค้า เพื่อนำมาใช้ประกอบการพิจารณาความเสี่ยง
* FR 3.5: ระบบต้องนำข้อมูลที่ดึงมาจากระบบ ERP และข้อมูลที่ผู้ใช้กรอก เข้าสู่กลไกการคำนวณคะแนนความเสี่ยง โดยอัตโนมัติ โดยระบบต้องแยกการใช้งานโมเดลการคำนวณ ที่แตกต่างกันตามประเภทคำขอเครดิต ระหว่า "ลูกค้าใหม่" และ "ลูกค้าขอวงเงินเพิ่ม"
3.8.4 กระบวนการพิจารณาอนุมัติ
* FR 4.1: ผู้จัดการภูมิภาค ผู้จัดการฝ่ายขาย เจ้าหน้าที่ฝ่ายการเงิน ผู้จัดการฝ่ายการเงิน และคณะกรรมการ ต้องสามารถเห็น "รายการเอกสารรออนุมัติ" บนหน้าจอหลักของตนเอง
* FR 4.2: ระบบต้องรองรับการเปิดอ่านเอกสารคำขอ โดยแสดงข้อมูลทั้งหมดที่ถูกบันทึก และสามารถคลิกดูหรือดาวน์โหลดไฟล์แนบทั้งหมดเพื่อตรวจสอบได้
* FR 4.3: ระบบต้องแสดงประเภทคำขอเครดิต วงเงินที่แนะนำ ให้ผู้อนุมัติเห็นอย่างชัดเจนเพื่อเป็นข้อมูลสนับสนุนการตัดสินใจ
* FR 4.4: ระบบต้องควบคุมการอนุมัติตามเงื่อนไขวงเงิน ดังนี้:
   * FR 4.4.1: กรณีมูลค่าวงเงินที่พิจารณา ไม่เกิน 300000 บาท ระบบต้องอนุญาตให้ ผู้จัดการฝ่ายการเงิน มีสิทธิ์เลือกดำเนินการอนุมัติวงเงินตามขอ ปรับแก้ไขมูลค่าวงเงินใหม่ หรือปฏิเสธคำขอ และสามารถกดปุ่ม “อนุมัติ” เพื่อสิ้นสุดกระบวนการได้ทันที
   * FR 4.4.2: กรณีมูลค่าวงเงินที่พิจารณา มากกว่า 300000 บาทขึ้นไป ระบบต้องอนุญาตให้ คณะกรรมการเครดิต มีสิทธิ์เลือกดำเนินการอนุมัติวงเงินตามขอ ปรับแก้ไขมูลค่าวงเงินใหม่ หรือปฏิเสธคำขอ และสามารถกดปุ่ม “อนุมัติ” เพื่อสิ้นสุดกระบวนการได้ทันที
* FR 4.5: เมื่อสิ้นสุดกระบวนการอนุมัติเครดิต ระบบต้องทำการแจ้งเตือน กลับไปยังผู้จัดการสาขา เพื่อแจ้งผลการพิจารณา วงเงินที่ได้รับอนุมัติ หรือเหตุผลในกรณีปฏิเสธ
3.8.5 กระบวนการตรวจสอบและติดตามสถานะ
* FR 5.1: ผู้จัดการสาขา ต้องสามารถเข้าหน้าจอ "คำขอทั้งหมด" เพื่อตรวจสอบสถานะปัจจุบันของคำขอเครดิตที่ตนเองส่งไปได้
* FR 5.2: ระบบต้องบันทึกกิจกรรมในระบบ โดยระบุอย่างละเอียดว่าใคร เป็นผู้ดำเนินการ ทำกิจกรรมใด และเกิดขึ้นในวัน-เวลาใด
3.8.6 ระบบการแจ้งเตือนภายใน
* FR 6.1: ระบบต้องส่งการแจ้งเตือนไปยัง Role ที่รับผิดชอบขั้นตอนถัดไปโดยอัตโนมัติทุกครั้งที่มีการเปลี่ยนสถานะคำขอ
* FR 6.2: ระบบต้องส่งการแจ้งเตือนไปยังผู้จัดการสาขาโดยตรงทุกครั้งที่สถานะเปลี่ยน เพื่อให้สามารถตรวจสอบ และติดตามความคืบหน้าได้
* FR 6.3: รายการแจ้งเตือน ต้องสามารถคลิก เพื่อเปิดเข้าสู่หน้าจอคำขอเครดิตที่เกี่ยวข้องได้
3.9 Non-Functional Requirements
3.9.1 ด้านความถูกต้องและความน่าเชื่อถือ
* NFR 1.1: การประมวลผลของ Scoring Engine จะต้องมีความถูกต้องแม่นยำ 100% เมื่อทดสอบกับชุดข้อมูลทดสอบมาตรฐาน ที่กำหนดไว้ล่วงหน้าก่อนการขึ้นระบบ
* NFR 1.2: ระบบต้องรับประกันว่าข้อมูลจะไม่สูญหาย ในขณะที่ผู้ใช้กด บันทึกฉบับร่าง หรือ ส่งอนุมัติ หากเกิดปัญหาระบบเครือข่ายขัดข้อง ระบบต้องมีกลไกจัดการข้อมูลและทำการส่งข้อมูลซ้ำอัตโนมัติ เมื่อเครือข่ายกลับมาใช้งานได้ปกติ
* NFR 1.3: ระบบต้องมีการสำรองข้อมูล ที่มีประสิทธิภาพ เพื่อรับประกันว่าหากระบบเกิดความเสียหายร้ายแรง ข้อมูลจะสูญหายย้อนหลังได้ไม่เกิน 24 ชั่วโมง
* NFR 1.4: ในกรณีที่ระบบหลักเกิดความล้มเหลว ระบบต้องสามารถกู้คืนระบบ และกลับมาให้บริการตามปกติได้ภายในเวลาไม่เกิน 4 ชั่วโมง
3.9.2 ด้านประสิทธิภาพการทำงาน
* NFR 2.1: หน้าจอหลัก และหน้าจอที่มีการโหลดข้อมูลรายการคำขอ ต้องแสดงผลข้อมูลครบถ้วนเสร็จสิ้นภายในเวลาไม่เกิน 3 วินาที สำหรับ 95% ของการทำรายการทั้งหมด
* NFR 2.2: กระบวนการคำนวณคะแนน และการแสดงผลคำแนะนำ ต้องใช้เวลาประมวลผลทั้งหมด ไม่เกิน 10 วินาที
* NFR 2.3: ระบบต้องสามารถรองรับผู้ใช้งานพร้อมกัน อย่างน้อย 100 คน ได้โดยยังคงผ่านมาตรฐานประสิทธิภาพตามที่ระบุใน NFR 2.1 และ NFR 2.2
3.9.3 ด้านความพร้อมใช้งาน
* NFR 3.1: ระบบต้องมีอัตราความพร้อมใช้งาน ไม่น้อยกว่า 99.5% ในช่วงเวลาทำการหลักของธุรกิจ คือ วันจันทร์ - วันเสาร์ เวลา 08:00 น. ถึง 18:00 น.
* NFR 3.2: ระยะเวลาระบบหยุดทำงานที่ไม่ได้วางแผนล่วงหน้า ต้องรวมกันไม่เกิน 4 ชั่วโมงต่อเดือน
* NFR 3.3: การปิดปรับปรุงระบบตามแผน ที่ส่งผลกระทบต่อการใช้งาน ต้องดำเนินการนอกเวลาทำการหลักเท่านั้น และระบบต้องส่งประกาศแจ้งเตือนผู้ใช้งานล่วงหน้าไม่น้อยกว่า 3 วันทำการ
3.9.4 ด้านความปลอดภัยและการตรวจสอบ
* NFR 4.1: ระบบต้องผ่านการทดสอบสิทธิ์การใช้งาน 100% เพื่อพิสูจน์ว่าไม่มีช่องโหว่การข้ามสิทธิ์การทำงาน เช่น พนักงานขายต้องถูกจำกัดไม่ให้เห็นปุ่ม อนุมัติวงเงิน หรือเข้าถึงข้อมูลหน้าจอวงเงินแนะนำสำหรับฝ่ายการเงิน
* NFR 4.2: บันทึกประวัติกิจกรรมสำคัญ ได้แก่ การสร้างคำขอเครดิต การอนุมัติ และการแก้ไขวงเงิน ต้องถูกจัดเก็บในรูปแบบที่อ่านได้อย่างเดียว โดยระบบต้องบล็อกไม่ให้ผู้ใช้งานทั่วไปรวมถึงผู้ดูแลระบบ สามารถแก้ไข ดัดแปลง หรือลบข้อมูล Log เหล่านี้ได้
3.9.5 ด้านความง่ายในการใช้งาน
* NFR 5.1: ข้อความแจ้งเตือนความผิดพลาด ที่แสดงผลบนหน้าจอผู้ใช้งาน 100% ต้องใช้ภาษาไทยที่ชัดเจน โดยอธิบายชัดเจนว่า เกิดปัญหาอะไรขึ้น และ ผู้ใช้ต้องแก้ไขอย่างไร โดยห้ามแสดงรหัสข้อผิดพลาดทางเทคนิค ให้ผู้ใช้ทั่วไปเห็นบนหน้าจอหลัก
3.9.6 ด้านการบำรุงรักษาและขยายระบบ
* NFR 6.1: สถาปัตยกรรมซอฟต์แวร์ของระบบต้องออกแบบในรูปแบบโมดูล เพื่อรองรับการขยายหรือเพิ่มประเภทเอกสารคำขอเครดิตรูปแบบใหม่ในอนาคต โดยโครงสร้างต้องเอื้อให้ใช้เวลาในการพัฒนาและทดสอบระบบ ไม่เกิน 40 ชั่วโมงทำงาน ต่อการเพิ่ม 1 ประเภทเอกสารคำขอเครดิตใหม่
3.9.7 ข้อกำหนดด้านสถาปัตยกรรมระบบเฉพาะเจาะจง
* NFR 7.1: ระบบต้องได้รับการออกแบบให้สามารถทำงานได้อย่างสมบูรณ์ภายใต้เครือข่ายภายในองค์กรที่ไม่เชื่อมต่ออินเทอร์เน็ตภายนอกได้ โดยในส่วนฟังก์ชันการส่งแจ้งเตือน ต้องพึ่งพาการทำงานภายในระบบเอง และห้ามพึ่งพาบริการภายนอก
* NFR 7.2: ระบบต้องสามารถจัดทำชุดโปรแกรมติดตั้งเป็นแพ็กเกจสำเร็จรูป เพื่อนำไปติดตั้ง บนระบบปฏิบัติการ Windows Server ได้โดยตรง โดยระบบต้องทำงานได้ทันทีโดยไม่ต้องทำการติดตั้งสภาพแวดล้อมจำลองเพิ่มเติม
3.9.8 ข้อกำหนดด้านความสมบูรณ์ของข้อมูล
* NFR 8.1: เพื่อรับประกันความถูกต้องของข้อมูลข้ามตาราง ระบบต้องทำการบันทึกข้อมูลที่เกี่ยวเนื่องกันหลายตารางในรูปแบบเป็นลำดับขั้นตอนที่แน่นอน  หากขั้นตอนใดขั้นตอนหนึ่งล้มเหลว ระบบต้องทำลายกระบวนการทั้งหมด ทันทีเพื่อไม่ให้เกิดข้อมูลค้างคา
* NFR 8.2: ก่อนที่ระบบจะอนุญาตให้ผู้จัดการสาขาทำการสร้างคำขอเครดิตใหม่ ระบบต้องบังคับให้มีการค้นหาและตรวจสอบฐานข้อมูลกลาง โดยใช้เลขประจำตัวประชาชนหรือเลขประจำตัวผู้เสียภาษี เพื่อตรวจสอบสถานะลูกค้าก่อนสร้างคำขอทุกครั้ง
3.9.9 ข้อกำหนดด้านการกู้คืนและทนทานต่อความเสียหาย
* NFR 9.1: ในกรณีที่ระบบทำงานประมวลผลข้อมูลแบบชุดอัตโนมัติ (Batch Automation Process) หากเกิดข้อผิดพลาดในรายการใดรายการหนึ่ง ระบบต้องจำกัดวงความเสียหายให้ขัดข้องเฉพาะรายการนั้น และต้องไม่ส่งผลกระทบต่อรายการอื่น ๆ ที่อยู่ในคิว (Queue) เดียวกัน โดยระบบต้องข้ามไปทำรายการถัดไปทันที
