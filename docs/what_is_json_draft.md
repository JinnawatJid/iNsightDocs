## 2.X รูปแบบข้อมูล JSON (JavaScript Object Notation)

**JSON (JavaScript Object Notation)** เป็นรูปแบบมาตรฐานเปิด (Open Standard) ที่ใช้สำหรับการจัดเก็บและแลกเปลี่ยนข้อมูล (Data Interchange Format) ซึ่งถูกออกแบบมาให้มีโครงสร้างที่มนุษย์สามารถอ่านและทำความเข้าใจได้ง่าย (Human-readable) และในขณะเดียวกันคอมพิวเตอร์ก็สามารถประมวลผล (Parse) และสร้างข้อมูล (Generate) ได้อย่างรวดเร็ว แม้ชื่อจะมาจากภาษา JavaScript แต่ปัจจุบัน JSON เป็นรูปแบบข้อมูลที่มีความเป็นอิสระจากภาษา (Language-independent) และได้รับการรองรับจากภาษาโปรแกรมมิ่งส่วนใหญ่ในปัจจุบัน

### 2.X.1 โครงสร้างของข้อมูล JSON
ข้อมูลในรูปแบบ JSON จะถูกจัดเก็บด้วยโครงสร้างข้อมูลพื้นฐาน 2 ลักษณะ ได้แก่:

1. **การจับคู่ระหว่างชื่อและค่า (Name/Value Pairs):** โครงสร้างนี้ในภาษาโปรแกรมต่างๆ อาจเรียกว่า ออบเจ็กต์ (Object), เรคคอร์ด (Record), พจนานุกรม (Dictionary) หรือ แฮชเทเบิล (Hash Table) โดยใน JSON จะใช้วงเล็บปีกกา `{ }` ครอบข้อมูล และคั่นระหว่างชื่อกุญแจ (Key) และค่า (Value) ด้วยเครื่องหมายโคลอน `:`
   *ตัวอย่าง:* `{"role": "Manager", "canApprove": true}`

2. **รายการของค่าที่เรียงลำดับ (Ordered List of Values):** โครงสร้างนี้มักเรียกว่า อาร์เรย์ (Array), ลิสต์ (List) หรือ ซีเควนซ์ (Sequence) โดยใน JSON จะใช้วงเล็บก้ามปู `[ ]` ครอบข้อมูล และใช้เครื่องหมายจุลภาค `,` คั่นระหว่างข้อมูลแต่ละตัว
   *ตัวอย่าง:* `["Branch A", "Branch B", "Branch C"]`

โดยค่า (Value) ที่จัดเก็บใน JSON สามารถเป็นได้ทั้งข้อความ (String), ตัวเลข (Number), ค่าทางตรรกศาสตร์ (Boolean - true/false), ค่าว่าง (null), ออบเจ็กต์ (Object), หรืออาร์เรย์ (Array) ซึ่งทำให้สามารถซ้อนข้อมูลกัน (Nested Data) เป็นโครงสร้างที่มีความซับซ้อนได้

### 2.X.2 จุดเด่นและการนำไปประยุกต์ใช้
ในอดีต ระบบคอมพิวเตอร์มักใช้โครงสร้างข้อมูลแบบ XML ในการแลกเปลี่ยนข้อมูล แต่ JSON ได้รับความนิยมมากขึ้นในปัจจุบันเนื่องจากข้อดีดังต่อไปนี้:
* **ความกระชับ (Lightweight):** ไม่มีแท็ก (Tag) เปิดปิดที่ซ้ำซ้อนเหมือน XML ทำให้ขนาดไฟล์หรือขนาดข้อมูลที่ต้องส่งผ่านเครือข่ายมีขนาดเล็กกว่า
* **การประมวลผลที่รวดเร็ว:** โครงสร้างข้อมูลสอดคล้องกับโครงสร้างข้อมูลพื้นฐานในภาษาโปรแกรมมิ่ง ทำให้กระบวนการแปลงข้อมูล (Parsing) ใช้ทรัพยากรน้อยกว่า
* **ความยืดหยุ่น (Flexibility):** ไม่จำเป็นต้องกำหนดโครงสร้างตายตัว (Schema-less) ทำให้สามารถเพิ่มหรือลดแอตทริบิวต์ได้ง่าย

ด้วยคุณสมบัติเหล่านี้ JSON จึงไม่ได้ถูกนำมาใช้เฉพาะเพื่อการรับส่งข้อมูลระหว่างเซิร์ฟเวอร์กับเว็บแอปพลิเคชัน (API Communication) เท่านั้น แต่ยังนิยมนำมาใช้เป็น **ไฟล์สำหรับการตั้งค่าระบบ (Configuration Files)** เนื่องจากผู้ดูแลระบบสามารถแก้ไขการตั้งค่าโครงสร้างข้อมูลที่มีความซับซ้อน (เช่น เงื่อนไข Workflow หรือค่าน้ำหนักตัวแปรใน Scorecard) ได้ผ่าน Text Editor ทั่วไป โดยไม่จำเป็นต้องแก้ไขและคอมไพล์โค้ดโปรแกรมขึ้นมาใหม่
