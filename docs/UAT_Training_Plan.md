# แผนการทดสอบระบบ (UAT Plan) - ระบบขออนุมัติเครดิต

เอกสารฉบับนี้จัดทำขึ้นเพื่อใช้ประกอบการทดสอบระบบก่อนการอบรม (Training Session) โดยมุ่งเน้นที่หน้าจอ **สร้างคำขอใหม่ (/create-credit-request)** และหน้า **คำขอรอดำเนินการ (/pending-requests)** ครอบคลุมผู้ใช้งาน 2 บทบาทหลัก คือ Maker (ผู้สร้างคำขอ/ผู้จัดการสาขา) และ Approver (ผู้อนุมัติ/ผู้จัดการภาคขึ้นไป)

---

## 🛠️ ข้อกำหนดเบื้องต้น (Prerequisites)
1. ติดตั้งและเปิดใช้งาน Backend และ Database เรียบร้อยแล้ว
2. สามารถเข้าสู่ระบบผ่านหน้าจอหรือมี User ทดสอบสำหรับ Maker และ Approver
3. เตรียมข้อมูลลูกค้าทดสอบ (รหัสลูกค้า หรือ ชื่อบริษัท) สำหรับการค้นหาและสร้างคำขอใหม่

---

## 🧑‍💻 1. บทบาท: Maker (ผู้จัดการสาขา / ผู้สร้างคำขอ)

### 📝 Test Case 1.1: การสร้างคำขอและบันทึกเป็นแบบร่าง (Save Draft)
**จุดประสงค์:** เพื่อทดสอบว่า Maker สามารถกรอกข้อมูลบางส่วนและบันทึกเป็นแบบร่าง (Draft) ได้ โดยข้อมูลไม่สูญหาย
**ขั้นตอนการทดสอบ:**
1. เข้าสู่ระบบด้วยสิทธิ์ **Maker**
2. ไปที่เมนู **"สร้างคำขอใหม่"** (`/create-credit-request`)
3. ในส่วน **"ค้นหาลูกค้า"** ให้พิมพ์ รหัสลูกค้า หรือ ชื่อบริษัท จากนั้นกดเลือกจากรายการค้นหา
4. กรอกข้อมูลบางส่วนในแท็บแรก (เช่น ข้อมูลทั่วไป)
5. กดปุ่ม **"บันทึกร่าง"** หรือฟังก์ชันเซฟสำหรับฉบับร่าง
6. รีเฟรชหน้าจอ (Refresh) หรือกลับไปที่หน้าหลัก แล้วกลับมาที่ **"สร้างคำขอใหม่"** (`/create-credit-request`)
7. ค้นหาลูกค้าคนเดิมอีกครั้งในแผงค้นหาด้านซ้าย
**ผลลัพธ์ที่คาดหวัง:**
- **สำคัญ:** รายการที่บันทึกเป็นแบบร่างจะ **ไม่ไปปรากฏ** ในหน้า "คำขอรอดำเนินการ" (`/pending-requests`) เพื่อแยกส่วนการทำงานที่ยังไม่เสร็จสิ้นออกจากคำขอที่รออนุมัติ
- เมื่อค้นหาและโหลดข้อมูลลูกค้าคนเดิม ข้อมูลที่กรอกค้างไว้ในแบบร่าง (Draft) จะต้องถูกโหลดกลับมาครบถ้วนเพื่อดำเนินการต่อ
- ปุ่มส่งคำขอและบันทึกการพิจารณาจะใช้งานได้ตามปกติเมื่อเข้าสู่แท็บสุดท้ายหรือมุมมองแสดงข้อมูลทั้งหมด

### 📊 Test Case 1.2: การจัดการลูกค้าในกรณี "ไม่มีงบการเงิน" (No Financial Data)
**จุดประสงค์:** เพื่อทดสอบการรับมือกับลูกค้านิติบุคคลที่ไม่มีข้อมูลทางการเงินในระบบ DBD
**ขั้นตอนการทดสอบ:**
1. สร้างคำขอใหม่ และเลือกแท็บ **"รายการเดินบัญชี"** (Store Statement / Financials)
2. หากเป็นลูกค้าบริษัทที่มีเลขทะเบียนนิติบุคคล แต่ระบบไม่สามารถดึงข้อมูลได้ ให้สังเกตสถานะการดึงข้อมูล
3. ติ๊กเครื่องหมายถูกที่ช่อง **"ลูกค้าไม่มีงบการเงิน"**
4. (หากมี) ลองแนบเอกสารเพิ่มเติม
**ผลลัพธ์ที่คาดหวัง:**
- แบดจ์สถานะแสดงข้อความเตือน หรือเครื่องหมายเช็คบ็อกซ์ "ลูกค้าไม่มีงบการเงิน" สามารถถูกเลือกได้
- ระบบยอมรับการตั้งค่านี้ และอนุญาตให้ไปทำรายการแท็บถัดไปได้ตามปกติ โดยไม่บังคับแจ้งเตือนเรื่องคะแนนทางการเงินจาก DBD

### 🚀 Test Case 1.3: การส่งคำขอที่สมบูรณ์ (Submit Request)
**จุดประสงค์:** เพื่อทดสอบกระบวนการส่งคำขออย่างเป็นทางการของ Maker
**ขั้นตอนการทดสอบ:**
1. กรอกข้อมูลให้ครบถ้วนทุกแท็บ รวมถึงเอกสารบังคับ (มีเครื่องหมาย *)
2. ในแท็บสุดท้าย หรือมุมมองรวม (แสดงข้อมูลทั้งหมด) ตรวจสอบปุ่มการกระทำ (Action Buttons)
3. พิมพ์ความเห็นในการขออนุมัติในช่อง **"ความคิดเห็น"**
4. กดปุ่ม **"ส่งคำขอ"**
5. กดยืนยันในกล่องข้อความ (Popup) ว่าต้องการยืนยันการทำรายการ
**ผลลัพธ์ที่คาดหวัง:**
- มีข้อความแจ้งเตือน "คำขอถูกส่งเรียบร้อยแล้ว"
- หน้าจอทั้งหมดจะถูกล็อคกลายเป็นโหมด **อ่านอย่างเดียว (Read Only)** ปุ่ม Action หรือกล่องความคิดเห็นจะถูกซ่อน
- คำขอจะเปลี่ยนสถานะจาก "ร่าง" เป็น **"รออนุมัติ"**

## 🛡️ 2. บทบาท: Approver (ผู้จัดการภาค / ฝ่ายสินเชื่อ)

### 🔍 Test Case 2.1: การค้นหาและตรวจสอบคำขอบนหน้า Dashboard
**จุดประสงค์:** เพื่อทดสอบว่า Approver เห็นคำขอที่รอดำเนินการถูกต้องและสามารถดูข้อมูลได้
**ขั้นตอนการทดสอบ:**
1. เข้าสู่ระบบด้วยสิทธิ์ **Approver** (เช่น ผู้จัดการภาค)
2. ไปที่เมนู **"คำขอรอดำเนินการ"** (`/pending-requests`)
3. ในแถบด้านซ้าย (Sidebar) ลองใช้ช่อง **"ค้นหาด้วย รหัสลูกค้า ชื่อ..."** พิมพ์หาคำขอที่เพิ่งส่งจาก Maker
4. คลิกเลือกคำขอนั้น
**ผลลัพธ์ที่คาดหวัง:**
- คำขอที่เพิ่งสร้างและมีสถานะตรงตามสิทธิ์จะแสดงในรายการ
- เมื่อคลิกดู ข้อมูลทั้งหมดของลูกค้าและคำขอจะต้องอยู่ในโหมด **อ่านอย่างเดียว (Read-only)** ไม่สามารถแก้ไขฟอร์มได้
- สามารถสลับแท็บเพื่อดูเอกสาร, ประวัติ และคะแนนเครดิตได้

### ✅ Test Case 2.2: การพิจารณาอนุมัติ (Approve)
**จุดประสงค์:** เพื่อทดสอบการทำงานของปุ่ม Workflow Approval
**ขั้นตอนการทดสอบ:**
1. ในหน้าของคำขอนั้น เลื่อนลงไปที่ส่วน **"บันทึกการพิจารณา"** (Credit Review Section) หรือแถบ **Workflow Action Bar**
2. พิมพ์ข้อความในช่อง **"ความคิดเห็น"** (เช่น "อนุมัติตามเสนอ")
3. กดปุ่ม **"อนุมัติ"**
4. กดยืนยันการทำรายการ
**ผลลัพธ์ที่คาดหวัง:**
- ระบบบันทึกการอนุมัติเรียบร้อย และเปลี่ยนสถานะคำขอเป็นขั้นตอนถัดไปหรืออนุมัติแล้ว
- รายการนั้นจะหายไปจาก Dashboard "รออนุมัติ" ของตนเอง (หรือถูกจัดกลุ่มในหมวดอื่น)
- ประวัติความเห็นในส่วนล่างจะปรากฏชื่อและข้อความที่พิมพ์ไป

### ❌ Test Case 2.3: การพิจารณาไม่อนุมัติ (Reject) (ทดสอบเพิ่มเติม - เสริม)
**จุดประสงค์:** เพื่อทดสอบกระบวนการปฏิเสธคำขอ
**ขั้นตอนการทดสอบ:**
1. เปิดคำขอรอดำเนินการขึ้นมา 1 รายการ
2. พิมพ์ความเห็นในช่อง "ความคิดเห็น" (เช่น "เอกสารไม่ครบ")
3. กดปุ่ม **"ไม่อนุมัติ"**
4. กดยืนยันการทำรายการ
**ผลลัพธ์ที่คาดหวัง:**
- สถานะคำขอเปลี่ยนเป็นไม่อนุมัติ
- คำขอนั้นหายไปจากรายการรอพิจารณา และจะกลับไปแสดงให้ Maker เห็น เพื่อที่ Maker จะสามารถใช้ปุ่ม "สร้างคำขอใหม่ (แก้ไข)" (Request Revision) ได้
